## 3. 异常项：Maven 在 Git Bash 下无法启动

### 3.1 现象

```
$ mvn -v
错误: 找不到或无法加载主类 org.codehaus.plexus.classworlds.launcher.Launcher
原因: java.lang.ClassNotFoundException: org.codehaus.plexus.classworlds.launcher.Launcher
```

### 3.2 排查过程

1. 定位安装位置：`command -v mvn` -> `/d/development/apache-maven-3.9.10/bin/mvn`（安装完整）。
2. 检查安装完整性：`boot/plexus-classworlds-2.9.0.jar` 与 `bin/m2.conf` **均存在**，文件大小正常。
3. 排除环境变量：手动导出 `M2_HOME` / `MAVEN_HOME` 后重试，**故障依旧** -> 不是环境变量问题。
4. 复现脚本路径解析：单独执行脚本中 `MAVEN_HOME` 与 `CLASSWORLDS_JAR` 的计算逻辑，
   两者均正确解析（`/d/development/apache-maven-3.9.10/boot/plexus-classworlds-2.9.0.jar`）。
5. `bash -x` 追踪 exec 行，得到决定性证据：

```
+ exec '.../javapath/java' \
    -classpath /d/development/apache-maven-3.9.10/boot/plexus-classworlds-2.9.0.jar \
    -Dclassworlds.conf=/d/development/apache-maven-3.9.10/bin/m2.conf \
    -Dmaven.home=/d/development/apache-maven-3.9.10 \
    ... org.codehaus.plexus.classworlds.launcher.Launcher -v
```

### 3.3 根因

脚本把 **POSIX 风格路径**（`/d/development/...`）直接传给了 **Windows 原生 `java.exe`**。
Windows 版 JVM 无法解析 `/d/...`，等于类路径为空，因此抛 `ClassNotFoundException`。
即：该 `mvn` shell 启动器在当前 Bash 环境下**跳过了 POSIX→Windows 的路径转换分支**。

### 3.4 验证修复

手动用 `cygpath -w` 转换路径后执行，Maven 正常启动：

```
Apache Maven 3.9.10 (5f519b97e944483d878815739f519b2eade0a91d)
Maven home: D:\development\apache-maven-3.9.10
Java version: 21.0.11, vendor: Oracle Corporation, runtime: C:\Program Files\Java\jdk-21.0.11
Default locale: zh_CN, platform encoding: UTF-8
OS name: "windows 10", version: "10.0", arch: "amd64", family: "windows"
```

（附带发现：该调用必须同时传 `-Dmaven.multiModuleProjectDirectory`，否则报
`system property is not set`。）

### 3.5 处置

已提供 `scripts/mvn.sh` 包装脚本，自动定位 Maven、转换路径并透传参数：

```bash
scripts/mvn.sh -v
scripts/mvn.sh clean package -DskipTests
```

在 PowerShell / CMD 中工作不受影响，可直接用 `mvn`。
