### 网络排障过程（记录，避免下次重复走弯路）

失败链：
- `git push`（mingw git 2.55）→ `Empty reply from server`
- 系统 Git 2.33.1 → `schannel: failed to receive handshake`
- 绕过代理直连 → `Failed to connect github.com port 443 ... Timed out`
- 换 OpenSSL 后端 → `Received HTTP code 502 from proxy after CONNECT`

诊断结论：本机所有 HTTPS 走代理 `http://127.0.0.1:9734`（来自环境变量 `https_proxy`）。
该代理**间歇性**对 `github.com` 的 CONNECT 返回 502 上游失败，而同一时刻
`api.github.com`、`www.baidu.com`、`registry.npmjs.org` 均返回 200。
**即：不是 GitHub 全局不可达，是代理对特定域名的间歇性上游故障。**

**解决办法：重试 + 用 `dangerouslyDisableSandbox: true` 跑 push。**
第三次尝试（换仓库后）直接成功。所以遇到 502 别急着改配置，**多试几次**。

- 两个 Git：mingw64 自带 `git 2.55.0.windows.3`（`which git` 命中）/

- `http.sslbackend=schannel`（全局配置）
- **无 SSH 密钥**（`~/.ssh` 为空），只能走 HTTPS
