## 项目定位

工作区下有三条产品线。前两条为**福建主题**，第三条是**独立赛道**（非福建主题），
三者按赛道 / 用户 / 场景 / 数据四维度互不重叠，只共用工程基建（云开发、TDesign）。

1. **遇光（yuguang-travel-app）** — 全栈旅行应用
   - 后端：Spring Boot（已覆盖 107 个 API）
   - 移动端：Flutter
   - 后台管理：Vue3
   - 附加模块：React + Three.js 3D 文物展示（assets 含 8 个中国文物 GLB 模型，置于 `public/models/`）
   - 占据赛道：**文旅 / 旅行服务**
2. **闽游蛙（暂定名）** — 模仿《旅行青蛙》的福建主题微信小程序游戏
   - 核心玩法：角色自主出游 / 寄回明信片 / 收集特产 / 好友互动
   - 福建元素融入目的地、道具与剧情（土楼、武夷山、闽南文化、地方美食）
   - 载体已定：**原生微信小程序 + TDesign**（非小游戏），详见 `docs/闽游蛙-载体选型备忘.md`
   - 占据赛道：**休闲游戏 / 收集养成**
3. **老年记事本（代号 elder-notes，2026-10-08 由「明白卡」转向）** — 面向 60–80 岁老人的极简记事小程序
   - 一句话定位：**记下来，别忘了，找得到。** 只做"记 / 看 / 改 / 删 / 找 / 提醒"六件事
   - 铁律：层级深度 ≤2（共 4 页）、不用 tabBar / 抽屉 / 长按菜单、所有图标必须配文字、
     无广告无诱导、无多指手势依赖
   - 占据赛道：**信息无障碍 / 老年数字包容**；为 2026 微信小程序开发大赛专门设计
   - 明确不做：多级文件夹、标签体系、富文本、账号体系、社交社区、深色模式
   - 详见 `apps/elder-notes/docs/需求与设计说明.md`（含 S1–S23 参考来源清单）
   - **前身「明白卡」**（群通知解构工具）已于 2026-10-08 停用方向，代码保留在
     `apps/mingbaika/`，其中 `core/time-parser.js` 作为可复用资产搬到新项目

## 本机环境约定

- Shell 用 **Git Bash**（用户习惯），但 `cmd.exe` 被安全策略禁止从 Bash 调用。
- **Java 项目在 Git Bash 下必须用 `scripts/mvn.sh` 构建**，直接用 `mvn` 会因路径未转换而
  `ClassNotFoundException`。详见 `docs/环境体检报告.md`。
- 工具链版本：Node 22.22.2 / Flutter 3.44.6 / Dart 3.12.2 / JDK 21.0.11 / Maven 3.9.10。
- `JAVA_HOME`、`M2_HOME`、`MAVEN_HOME` 在本机均为空。

## 适老化设计 · 硬性数值（老年记事本沿用，勿凭印象改）

合规类指标只采信官方源，已换算为小程序 rpx（750rpx = 375pt，1pt = 2rpx）：

- 字号：正文起步 20pt（40rpx），三档 20/24/28pt；**辅助文字绝不低于 16pt（32rpx）**
  （工信部《APP 适老化通用设计规范》：适老版主要文字 ≥18pt，最大 ≥30pt）
- 对比度：一律 ≥4.5:1，**不采用"大字号可降到 3:1"的宽松档**；主色避蓝色（老人辨色力下降）
- 热区：主要组件 ≥60×60pt = **120rpx**；次要 ≥44×44pt = **88rpx**；元素周围加 12pt 热区
- 行距 ≥1.5（规范底线 1.3）；微信「关怀模式」再乘 1.4，字号设计要留余量
- 删除**不弹确认框**，改用大号撤销条（Material / Apple HIG 的 undo 优先原则）
- 语音：微信「同声传译」插件**不对个人主体开放** → 不自建 ASR，引导用输入法自带话筒
- 提醒：小程序**做不到闹钟式主动响**（一次性订阅=1次授权1条）→ 主方案是"打开即见"

## 明白卡（mingbaika）· 架构定调（2026-10-08，方向已停用，仅存档）

- **核心功能已去 AI 依赖**，改为**小程序端纯本地规则引擎**（无可用 AI 额度）。
  方案见 `apps/mingbaika/docs/技术方案-纯本地版.md`。
- 铁律：**ActionCard Schema v1.0 是唯一契约，不得改动**。
  本地抽取器必须产出**与 AI 输出同构**的 JSON，以便将来换回 AI 时下游零改动。
- 解析引擎放在**小程序端**（不是云函数）——为弱网可用，也为将来"端上规则先行 +
  失败上云调 AI"的分层留出空间。
- 图片识别不做（本地无可用 OCR），引导用户用微信自带「长按图片→提取文字」。
- 已知可复用资产：`core/` 的 time-parser / risk-rules / schema **完全不依赖 AI**。
