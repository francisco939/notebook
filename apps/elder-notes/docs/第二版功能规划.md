> 版本：v1.0　编制日期：2026-10-09

## 0. 一句话结论

第一版是**合格的"能用的记事本"，但还不是"老人会天天打开的记事本"**。
最大的三个短板是：**重复的事得天天重记、做完的事没法打勾、换手机全没了**。

第二版建议只做 **4 个 P0**，全部是**加字段 + 加视图**级别的改动，
**不动解析内核、不引入新架构、不改存储结构**，且对体验版已有数据**向后兼容**。

## 2. 竞争力短板分析（对标同类产品）

对标对象：**敬业签**（小程序便签头部，功能最全）、**Google Keep / 苹果备忘录**（系统自带，零门槛）、
**Medisafe / Memoryboard**（老年垂直），以及微信自带的「收藏」+「群待办」。

### 短板一：重复事项要天天重记 —— **最致命**

老人最高频的记事是**吃药、量血压、接孙子**——全是重复的。
现在每记一次只产生一个 `dueAt`，做完就过期，**第二天得重新打一遍字**。

竞品全都有：敬业签支持按天/周/月/年循环 + 农历；Todoist 支持自然语言重复。
而老人打字本来就慢（手写/拼音），**这个短板直接决定他会不会第二天弃用**。

> 判断依据：`store.js` 的 note 结构只有 `dueAt` 单值，无 `repeat` 字段。

### 短板二：做完的事只能删 —— 没有"完成感"

当前只有「留着」和「删掉」两种归宿。老人做完一件事后：
删了怕记错，不删又越堆越多、找不到今天还剩几件。

竞品（敬业签、Keep）都有打勾 + 已完成归档。这是**留存的核心心理机制**——
打勾带来的完成感是日用型工具的主要黏性来源。

### 短板三：数据只在本地，换手机/清缓存全丢

`store.js` 全走 `wx.setStorageSync`，按用户隔离、**不跨设备**。
老人换手机、微信清缓存、重装小程序 = 全部消失，且**没有任何补救途径**。

竞品几乎全部云同步（敬业签多端同步、Keep 跨设备、Medisafe 云端）。
这是**信任层面的短板**：他不敢把重要的事交给你。

### 短板四：触达弱，只能"打开才看见"

设计文档已诚实说明：小程序做不到闹钟式提醒，主方案是"打开即见"。
但这意味着**用户必须记得打开**——对记忆力衰退的目标人群，这是个循环依赖。

### 短板五：入口与日期感知弱

首页直接是搜索框 + 列表。**没有日期条**。
竞品里的 Dementia Clock 类产品的核心卖点恰恰就是"大字日期 + 星期"——
认知衰退用户最常问的是"今天几号、星期几"。这个我们**一行没做，但成本极低**。

### 短板六：无家庭协同

老年垂直产品（Memoryboard、Medisafe MedFriend）的共识是：
**真正的用户是照护者，不是老人本人**。我们目前完全没有"让子女知道"的通路。

## 3. 候选功能清单（6+2）

> 筛选标准：① 复用现有模块 ② 不引入新架构 ③ 用户感知强 ④ 可在真机上当天验证。
> **工作量按熟练前端单人估算**；"低"≈0.5 人天内，"中"≈1–1.5 人天。

---

### F1 · 重复记事（每天 / 每周 / 每月）

| 项 | 内容 |
|---|---|
| **痛点** | 吃药、量血压这种每天的事，现在得每天重打一遍字。老人打字慢，几天就弃用 |
| **思路** | note 增加 `repeat: 'none'\|'daily'\|'weekly'\|'monthly'`（**可选字段，老数据没有即 `none`，零破坏**）。<br>**不做实例化**（不生成 N 条记录），只在首页渲染时判断"这条今天该不该出现"：有 `repeat` 时忽略 `dueAt` 的日期部分，只比时间。<br>完成状态记在 `doneDates: ['2026-10-09']`，当天打勾后当天不再显示 |
| **复用** | `time.js` 的 `dateText()` 生成日期键、`display()` 显示时间；`store.update()` 的 patch 语义天然支持加字段；`edit.js` 已有的 `pickQuick` 按钮组直接扩一格 |
| **工作量** | **中（1 人天）** — 主要在"重复项投影到今天"的判断逻辑和完成态清理 |
| **收益** | ★★★★★ 直接消除最高频的重复劳动，是"能不能天天用"的分水岭 |
| **验收** | 记一条"每天 8 点 吃药" → 连续 3 天打开，每天都出现在"今天要做的事"；打勾后当天消失，次日再现 |

---

### F2 · 打勾「做完了」+ 已完成区

| 项 | 内容 |
|---|---|
| **痛点** | 做完只能删。删了怕记错，不删越堆越多，不知道今天还剩几件 |
| **思路** | 列表项右侧加大号 ✓ 按钮（≥120rpx）。点击 → `update(id, {doneAt, done:true})` → 加删除线 + 移入底部"做完了"折叠区（默认折叠，不占视野）。<br>**复用软删除的同一套"可逆"心智**：做错了再点一次取消 |
| **复用** | `store.update()`、首页分组逻辑、`undo` 的视觉规范 |
| **工作量** | **低（0.5 人天）** |
| **收益** | ★★★★★ 完成感是日用工具的主要留存机制；顺带解决"列表越用越乱" |
| **验收** | 打勾后该项带删除线并移到"做完了"；再点取消可恢复；已有数据（无 `done` 字段）照常显示 |

---

### F3 · 云备份与恢复（换手机不丢）

| 项 | 内容 |
|---|---|
| **痛点** | 数据只在本地，换手机/清缓存全丢，且无补救途径。用户不敢把重要的事交给你 |
| **思路** | **小程序端直连云开发数据库**，不新增云函数（省掉一次手动部署）。<br>集合 `notes`，权限「仅创建者可读写」→ 天然按 openid 隔离。<br>本地仍为权威；联网时静默增量同步（按 `updatedAt`）；**同步失败静默降级**，老人体验不退化。恢复入口放设置页：「从云端找回」 |
| **复用** | `store.js` 已有 `updatedAt` 字段，天然支持增量同步；设置页已有「只放能用的东西」的框架 |
| **工作量** | **中（1–1.5 人天）** + 外部依赖（控制台建集合，约 5 分钟，你必须操作） |
| **收益** | ★★★★★ 信任层面的补齐；也是参赛材料里"数据可靠性"的依据 |
| **验收** | A 手机记 3 条 → 同步 → B 手机登录同一微信 → 找回 3 条；断网时仍能正常记，联网后自动补传 |

---

### F4 · 常用短语一键插入（含高频词自动提取）

| 项 | 内容 |
|---|---|
| **痛点** | 老人打字慢（手写/拼音），而记的内容高度重复（吃药、量血压、接孙子） |
| **思路** | edit 页输入框上方放 3–5 个大按钮，点了直接插入文字。<br>**取巧点**：按钮内容不写死，从 `store.list()` 里**统计该用户历史记事的开头 3–4 字高频词**自动生成，越用越准；冷启动时用内置默认词（吃药 / 量血压 / 接孩子 / 买菜 / 交费） |
| **复用** | 参照 `edit.js` 现有的 `pickQuick` **照抄一套**——但注意 `pickQuick` 填的是时间字段 `rawTime`，<br>常用短语要追加到正文 `content`，所以要新写一个 `pickPhrase()`（约 8 行），**不是直接复用**。<br>按钮布局与 `hover-class`、触感反馈直接沿用同一套写法 |
| **工作量** | **低（0.3 人天）** |
| **收益** | ★★★★☆ 把"打字"降成"点一下"，输入门槛下降最明显的一项 |
| **验收** | 冷启动显示默认词；记过 3 条"吃药"后，按钮自动变成"吃药" |

---

### F5 · 首屏大日期条（含星期）

| 项 | 内容 |
|---|---|
| **痛点** | 认知衰退用户最常问"今天几号、星期几"。首页现在直接是列表，没有时间锚点 |
| **思路** | 首页顶部加一行大字：「10月9日 星期四」。字号随档位缩放（复用 `--font-title`）。<br>可选加一句状态摘要："今天有 3 件事" |
| **复用** | `time.js` 已有 `bjDateStr()`；星期计算是 5 行代码；`app.wxss` 的 CSS 变量直接生效 |
| **工作量** | **低（0.2 人天）** |
| **收益** | ★★★☆☆ 成本几乎为零，但对目标人群是真实的日常锚点（Dementia Clock 类产品的核心卖点） |
| **验收** | 打开首页第一行显示正确日期与星期；切字号三档都正常 |

---

### F6 · 一键复制给家人（兼作手动备份）

| 项 | 内容 |
|---|---|
| **痛点** | 老人记了但家人不知道；同时在没有云备份时，**没有任何自救手段** |
| **思路** | detail 页与设置页各加一个大按钮「发给家人」→ `wx.setClipboardData()` 复制成纯文本（内容 + 时间），Toast 提示"已复制，去微信里粘贴给孩子"。<br>设置页再加「全部复制」→ 拼接所有记事，作为**无云备份时的手动备份方案** |
| **复用** | 纯调用微信 API，零后端、零新增页面 |
| **工作量** | **低（0.3 人天）** |
| **收益** | ★★★★☆ 同时解决"家庭协同"和"备份自救"两件事，成本极低 |
| **验收** | 点后粘贴到微信输入框，文本完整、时间可读 |

---

### F7 · 订阅消息提醒（一次性）

| 项 | 内容 |
|---|---|
| **痛点** | 只能"打开才看见"，而目标人群恰恰记不住打开 |
| **思路** | 保存带时间的记事时，顺带请求一次 `wx.requestSubscribeMessage` 授权，到期由**云函数**发送一条服务通知。<br>**必须诚实**：一次授权只能发一条；老人大概率不会主动授权；且**需要新增 1 个云函数**（打破当前"纯端上、无云函数"的状态） |
| **复用** | 无现成模块可复用，需新写云函数 |
| **工作量** | **中（1–1.5 人天）** + 外部依赖（申请订阅消息模板，有审核周期，工具类可能被拒） |
| **收益** | ★★☆☆☆ 授权率低、只能发一次、模板可能申请不下来。**性价比最低的一项** |
| **验收** | 授权后能在指定时间收到 1 条服务通知 |

---

### F8 · 高对比模式

| 项 | 内容 |
|---|---|
| **痛点** | 部分老人有白内障/黄斑变性，4.5:1 的对比度仍不够 |
| **思路** | 设置页加一个大开关，切换后通过 `app.wxss` 的 CSS 变量整体换成黑底黄字/白底黑字高对比配色 |
| **复用** | **完全复用已有的 CSS 变量体系**，只改变量值，不动任何页面结构 |
| **工作量** | **低（0.3 人天）** |
| **收益** | ★★☆☆☆ 覆盖人群有限；当前配色已达标规规范，属于锦上添花 |
| **验收** | 开关切换后全站配色变化且对比度不低于 4.5:1（`scripts/check.js` 可扩展检查） |

## 5. 依赖关系与上线节奏

### 5.1 依赖图

```
F4 常用短语 ──┐
              │
F5 日期条 ────┼── 互相独立，可任意顺序、可并行
              │
F6 复制分享 ──┘

F2 打勾完成 ──────┐
                  ├──> F1 重复记事（重复项的"今天做完了"要复用 F2 的完成态字段）
                  │
F1 重复记事 ──────┘

F3 云备份 ──── 依赖【你在控制台建 notes 集合】（外部，约 5 分钟）

F7 订阅消息 ── 依赖【新增云函数】+【订阅模板审核通过】← 两个都不确定
```

**关键依赖只有两条**：
1. **F1 依赖 F2** —— 重复记事需要"今天已完成"这个状态，正是 F2 引入的。所以**先做 F2 再做 F1**，否则要返工。
2. **F3 依赖你在控制台建集合** —— 我可以写脚本自动建（之前给明白卡写过 `setup-db.js`，但已随旧项目归档），但**需要 AppSecret**，且权限需人工核对。

### 5.2 推荐节奏（距 10/17 还有 8 天）

| 阶段 | 内容 | 产出 | 验证方式 |
|---|---|---|---|
| **M1**（第 1 天） | F4 + F5 + F2 | 端上三件套，零外部依赖 | 开发者工具模拟器 + 你的手机 |
| **M2**（第 2–3 天） | F1（依赖 F2）+ F6 | 重复记事上线 | 记"每天 8 点吃药"，连续 3 天验证 |
| **M3**（第 4–5 天） | F3（你先建集合） | 云备份可用 | 换设备/清缓存验证恢复 |
| **M4**（第 6–8 天） | **真机验证 + 修 bug** | — | **找一位真实长辈试用** |

> ⚠️ **M4 不要压缩**。前 5 天的功能再漂亮，没经过老人真实使用都不算数。
> 这是参赛材料里唯一无法伪造的说服力来源。

### 5.3 兼容性承诺（硬约束）

所有新增字段（`repeat` / `done` / `doneDates` / `syncedAt`）**必须是可选字段**：

- 旧数据没有该字段时，代码按默认值处理，**不得报错、不得清空**
- `store.update(id, patch)` 已支持局部更新，天然满足
- **体验版已有用户的数据不受影响** —— 这条要在上线前用真实数据验证一次

| 风险 | 影响 | 应对 |
