## 2. 与原定位的三处冲突，以及怎么处理的

原定位是「老年极简记事本」，铁律包括"极简、无诱导、层级 ≤2、字号热区是生命线"。
这次的闯关化改造与它有冲突，处理方式如下——**这些是决策，不是技术细节，改动前先看这里**。

| 冲突 | 处理 |
|---|---|
| **游戏化（关卡/闯关）vs 适老化无诱导** | 只借用"关卡 + 进度"的**叙事外壳**，不引入积分、排名、奖励、分享拉新等诱导机制。字号、热区、对比度**一个数值都没放宽** |
| **日历 vs 老人不会探索** | 日期条只能横滑和单击，点一下筛选、再点一下还原；不依赖长按/双击/滑动删除 |
| **家人添加事件 vs 无账号体系** | 不做账号、不做云端多用户。添加人 = 本地存的一个名字（设置页可改），记一条时自动带入。零依赖，也零成本 |

> ⚠️ 需要你判断的一点：如果本项目仍要按"适老化"参赛，**"关卡"这个词本身可能被认为带有诱导性**。
> 真机验证时如果发现长辈对"第 N 关"没感觉甚至困惑，建议把文案退回"10月9日 周五"的纯日期表述，
> 只保留进度条——进度感保留，游戏化措辞去掉。这个改动只需改一行 wxml。

## 3. 数据模型（全部向后兼容）

```
Note {
  ...原有字段（content / rawTime / hasTime / dueAt / createdAt / updatedAt / deleted）...

  title:    string   // 事件标题。老数据没有 → 用 content 首行兜底
  status:   'todo' | 'done' | 'skipped'   // 老数据没有 → 按 'todo'
  statusAt: number|null
  author:   string   // 添加人。老数据没有 → 空
}
```

**兼容是硬约束**：体验版可能已有真实数据，新字段一律可选、一律给兜底值，
不得报错、不得清空。已在 `scripts/quest.test.js` 第 5、6 节用老数据结构专门验证。

老记事被编辑一次时会自动拆成"标题 = 正文首行 / 描述 = 其余"，
即编辑即迁移，不需要写迁移脚本。

---

## 4. 关卡规则

- **归属日期**：优先 `dueAt`（事件预定发生的那天）；没有就用 `createdAt` 兜底，
  保证每条事件一定落在某一关，不会无家可归
- **关卡号**：按日期升序从 1 开始，最早那天是第 1 关
- **进度条**：完成 + 跳过都算"已处理"
- **软删除**：在 `buildLevels` 内部再过滤一次，不依赖调用方

## 6. 顺手修掉的一个检查脚本 bug

`scripts/check.js` 的"可点元素必须有文字"检查，原来从 `bindtap` 所在行向后只看 4 行。
当标签属性跨多行展开时（`bindtap` 在第 1 行、文字在十行之后），会**误报**。
且属性里的 `data-id="{{x.id}}"` 会被当成"有文字"，造成漏报。

已改为：先定位这个标签结束在哪一行（找 `>`），**只检查标签体**，
不再把属性行算进来。这次首页卡片就是被误报的那处。
