## 1. 入口 A：`wx.chooseMessageFile`（从聊天记录选图片）—— 主入口

### 为什么必须在真机上测

- 微信官方文档与社区回复均明确：**该接口不支持在微信开发者工具中调试，必须真机**。
- 社区里另有一说"开发工具上可以正常使用"，两种说法**冲突**，我没有实测过，无法判定谁对。
  因此标准做法是：**工具里先点一次、把现象记下来，但结论以真机为准。**

### 步骤与通过标准

| 步骤 | 操作 | 通过标准 | 失败时的典型报错 |
|---|---|---|---|
| A1 | 工具里点「从聊天选图片」 | 记录现象即可（不作为判定依据） | — |
| A2 | 手机真机打开小程序，点「从聊天选图片」 | 弹出微信的聊天记录选择界面 | 无反应 / `fail` 无回调 / `scope is not declared...` |
| A3 | 选中一张**群里发的通知截图** | `tempFiles[0].path` 有值，且**能正常上传到云存储** | `fail` 回调 |
| A4 | 等待解析，落到结果页 | 出现行动卡，或降级为原文（都算通过） | 一直转圈 / 报「上传失败」 |

### 已知坑（代码里已规避，无需你再处理）

- **`type` 必须传 `'image'` 或 `'all'`，不能传 `'file'`。**
  真机上 `type:'file'` **选不到图片和视频**（开发者工具里却能选到，属于平台行为差异）。
  我们的代码用的是 `type: 'image'` ✅
- 首次进入就点可能没反应，退出小程序重进才正常——这是社区反馈过的时序问题，
  真机测试时请**分别记录「首次进入就点」和「重进后再点」两种情况**。

### 要记录的关键结论

- [ ] 真机能否弹出选择界面
- [ ] 选中的截图能否上传成功（拿得到 fileID）
- [ ] 「首次进入」与「重进」行为是否不同

## 2. 入口 B：转发聊天素材打开小程序（scene 1173）—— 差异化入口

### 机制（已按官方文档核对）

用户在聊天里打开一张**图片/文件/视频**时，打开方式里会多出「用明白卡看懂」这一项，
点它就带着素材进入小程序，启动参数 `scene = 1173`，并携带 `forwardMaterials` 数组。

### 硬约束（都要满足，任何一个不满足入口就不出现）

| 约束 | 说明 |
|---|---|
| 平台 | **仅 Android**。iOS 不支持该入口。 |
| 基础库 | ≥ 2.14.3 |
| 微信版本 | 图片需 ≥ **8.0.1**，文件和视频需 ≥ 8.0.0 |
| 配置 | `app.json` 声明 `supportedMaterials` —— **本次已补上** |
| 审核 | **提审时会审核该声明**，通过后入口才会出现 |
| 用户 | 正式版还要求**用户曾经使用过该小程序** |
| 图片限制 | **带二维码的图片不支持**直接用小程序打开（缴费通知里常带收款码，注意） |

### 开发者工具里怎么调

在开发者工具中新建**自定义编译模式**，把场景值设为 **1173**，即可在工具里调试这条路径。

### 步骤与通过标准

| 步骤 | 操作 | 通过标准 |
|---|---|---|
| B1 | 上传体验版（体验版可**独立配置** `supportedMaterials`，与正式版互不影响） | 上传成功 |
| B2 | Android 手机，长按群里的**通知截图** | 打开方式列表中出现「用明白卡看懂」 |
| B3 | 点它 | 进入小程序并自动开始解析 |
| B4 | 观察 `forwardMaterials[0]` | 记录 `type` / `name` / **`path` 的真实形态** |

### ⚠️ B4 是这条入口最关键的观测点

代码里 `uploadFromMaterialPath` 对 `path` 做了两条分支：
http(s) URL → 先 `wx.downloadFile`；本地临时路径 → 直接上传。

**官方文档对该字段的表述是「文件路径或 URL」，两种都可能**，我没实测过，不敢假定。

- 若真机报 `downloadFile:fail url not in domain list`
  → 说明给的是微信域名的 URL，客户端拿不到。
  **修法：把 URL 直接交给云函数去取**（云函数出网不受合法域名白名单限制）。
  这是已知的可行退路，不用慌。

请记录：`path` 长什么样（是 `/tmp/...` 还是 `https://...`），以及是否报域名错误。

## 6. 本次已按平台文档修掉的 3 个缺陷

写这份清单时对照官方文档核对代码，发现并修掉了三个**会让入口静默失效**的问题：

1. **`app.json` 缺 `supportedMaterials` 声明** → 入口 B **根本不存在**。
   首页当时写着"长按通知 → 转发 → 明白卡"，是一句做不到的承诺。已补声明。
2. **`app.js` 读 `forwardMaterials` 的位置错了** → 官方规定该数组与 `query` **同级**，
   原代码去 `query` 里找，永远取不到。已改为从启动参数与 `wx.getEnterOptionsSync()` 读取。
3. **上传函数只接受本地临时路径** → 素材 `path` 若是 URL 会直接失败。已补 URL 分支。

另外修正了首页文案：原来说明"长按通知转发"，
但 `supportedMaterials` 只覆盖**图片/文件/视频/webview 素材，不含聊天里的文字消息**。
所以文字通知转发不了，必须先截图。已改成如实指引（图片→长按转发；文字→截图；纸质→拍照）。

> 这条"文字消息不能转发"是**我根据官方文档的素材类型表推断的**，
> 没有真机验证。请在真机上顺手确认：长按一条**纯文字**消息，看打开方式里有没有明白卡。
