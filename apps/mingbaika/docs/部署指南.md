# 明白卡 · 部署指南

> 目标：把 `apps/mingbaika/` 的代码变成一个能在微信里打开的体验版，再变成正式线上版本。
> 本文只讲**部署**。三个通知入口能否跑通是另一件事，见 `入口实测清单.md`。

---

## 一、先看清分工：哪几步我做不了

部署一条小程序，其实是 5 个动作。其中 **3 个必须由账号持有者本人操作**，脚本无法代劳——不是技术问题，是微信的权限模型决定的：

| # | 动作 | 谁做 | 说明 |
|---|---|---|---|
| 1 | 注册主体、拿到 AppID | **你** | 需要实名/企业资质，且管理员的身份验证无法外包 |
| 2 | 开通云开发、拿到环境 ID | **你** | 在开发者工具里点开通，要确认套餐与实名 |
| 3 | 下载代码上传密钥 + 配 IP 白名单 | **你** | 密钥只在公众平台生成一次，不会明文存储；白名单是防泄露的关键开关 |
| 4 | 部署云函数 + 上传代码 | ✅ **已自动化** | `node scripts/deploy.js all` |
| 5 | 提交审核 → 发布 | **你** | 后台点按，且有官方审核周期（1–7 天） |

所以答案是：**能帮到第 4 步，第 1、2、3、5 步只能你来做——但第 4 步以前需要你手工点的东西，我都压成了脚本和检查项。**

## 二、部署脚本：为什么不用开发者工具自带 CLI

微信官方本来有两条自动化路线。**我选了 `miniprogram-ci`，不是随便选的**——开发者工具 CLI 在你这台机器上根本用不了：

```
$ cli.bat islogin --project ...
× #initialize-error: Error: listen EACCES: permission denied 127.0.0.1:3799
```

根因不在沙箱，在 Windows 自己：

```
$ netsh int ipv4 show excludedportrange protocol=tcp
开始端口    结束端口
      3713        3812        ← 3799 落在这里面
```

Windows 的 `winnat`（Hyper-V 相关）把 **3713–3812** 整段保留了，而开发者工具 CLI 的桥接端口**硬编码为 3799**，所以它必然 `EACCES`。`--port` 参数改的是 IDE 的 HTTP 端口，改不了这个桥接端口，我实测过，依旧报 3799。

`miniprogram-ci` 是官方从开发者工具里抽离的编译模块，**不依赖开发者工具、不占 3799**，本来就是给 CI/CD 用的。对比：

| | 开发者工具 CLI | **miniprogram-ci** |
|---|---|---|
| 依赖 | 必须先起开发者工具 | 独立运行 ✅ |
| 端口 | 占用 3799 ❌ 本机被系统封 | 不固定端口 ✅ |
| 认证 | 工具登录态 | 代码上传密钥 |
| 云函数部署 | 支持 | 支持（`ci.cloud.uploadFunction`） |
| 本机可用性 | **不可用** | 可用 |

> 如果你哪天想恢复开发者工具 CLI，办法是管理员权限执行 `net stop winnat` → 释放端口段 → `net start winnat`，或在「设置 → 安全设置」里把服务端口改成段外。**这一步要动系统网络配置且需管理员，我没有替你执行。**

## 三、你需要做的三件事（按顺序）

### 步骤 1 · 确认主体与 AppID

先回答一个问题：**你手上有没有「7 月 17 日之后注册、且从未上线」的小程序主体？**

- **有** → 直接用它，符合本届「作品须在 7.17–10.17 期间全新上线」的门槛
- **没有** → 新注册一个。注意：个人主体可选类目有限（工具类通常可选），且**名称和类目提交后修改成本高**，一次想清楚

拿到 AppID 后，改这里：

```jsonc
// apps/mingbaika/project.config.json
{
  "appid": "wxXXXXXXXXXXXXXXXX",   // ← 换成你的
  ...
}
```

### 步骤 2 · 开通云开发，填 ENV_ID

1. 打开微信开发者工具 → 导入项目，目录选 `C:\Users\nihao\Desktop\FJTravel\apps\mingbaika`
   （注意：**选 `apps/mingbaika`，不是 `miniprogram`**。`project.config.json` 在 `apps/mingbaika` 根下，它负责指向 `miniprogram/` 和 `cloudfunctions/`）
2. 点顶部「云开发」→ 开通 → 选环境名（建议 `mingbaika-prod`）→ 记下**环境 ID**
3. 环境 ID 通常是 `环境名-随机串` 的形式，例如 `mingbaika-prod-8gxxxxxx`

填到这里（**只有这一处**，脚本会从这读，不用再填第二遍）：

```js
// apps/mingbaika/miniprogram/app.js  第 5 行
var ENV_ID = 'mingbaika-prod-8gxxxxxx';   // ← 换成你的
```

顺便在云开发控制台**手建一个集合 `notices`**（云函数用来落库去重）。权限建议「仅创建者可读写」。

### 步骤 3 · 拿代码上传密钥 + 配 IP 白名单

1. 登录 [微信公众平台](https://mp.weixin.qq.com) → 管理 → 开发管理 → 开发设置 → **小程序代码上传**
2. 点「生成」（或「重置」）→ 下载得到一个 `private.wxXXXX.key` 文件
3. **配 IP 白名单** —— 官方原文：「未配置 IP 白名单的，将无法使用 miniprogram-ci 进行预览和上传」。可以选「不限制」，但风险自负；如果开白名单，要加你本机的公网出口 IP
4. 把 `.key` 文件放到 `apps/mingbaika/` 根目录

```bash
# 放好后目录长这样
apps/mingbaika/
├── private.wx1234567890abcdef.key   ← 密钥（已在 .gitignore 中，不会进仓库）
├── project.config.json
├── miniprogram/
└── cloudfunctions/
```

> ⚠️ **密钥泄露 = 别人可以发布你的小程序。** 我已把 `*.key`、`private.*.key`、`deploy.config.json` 加进 `.gitignore`。**不要手动 `git add -f` 绕过它。**

## 四、执行部署（第 4 步，已自动化）

先装一次依赖（`miniprogram-ci`，装到 `node_modules/`，已被忽略）：

```bash
cd apps/mingbaika
npm install
```

然后按顺序跑：

```bash
# ① 前置检查 —— 先跑这个，它会明确告诉你还缺什么
node scripts/deploy.js check

# ② 部署云函数（首次云端装依赖约 1–3 分钟）
node scripts/deploy.js fn

# ③ 生成预览二维码，先自己扫码验一遍
node scripts/deploy.js preview

# ④ 上传代码 → 版本管理里会出现一个「开发版本」
node scripts/deploy.js upload 0.1.0 "明白卡 首个可测版本"

# 或者一步到位：云函数 + 上传
node scripts/deploy.js all 0.1.0 "明白卡 首个可测版本"
```

脚本有几个刻意的设计：

- **上传前强制跑静态校验**（`scripts/check.js`，77 项）。校验不过就直接中止上传——避免把「一打开就报错」的版本传上去。这个闸门是自动的，不用你记得跑。
- **AppID / ENV_ID 只在各自的原始文件里存一份**，脚本读出来用。不存在「脚本里填了但 app.js 忘了改」这种错位。
- **失败时给可用指引**，不是抛一段栈。

### 命令速查

| 命令 | 作用 |
|---|---|
| `node scripts/deploy.js check` | 前置检查（默认命令，不带参数也是它） |
| `node scripts/deploy.js fn` | 部署云函数 `parseNotice` |
| `node scripts/deploy.js preview` | 生成预览二维码 → `preview-qrcode.jpg` |
| `node scripts/deploy.js upload [版本] [备注]` | 上传代码 |
| `node scripts/deploy.js all [版本] [备注]` | 云函数 + 上传 |
| `node scripts/deploy.js -h` | 帮助 |

也可以用 npm scripts：`npm run deploy:all`、`npm run deploy:fn` 等。

## 五、最后一步：提审与发布（只能你来）

1. 公众平台 → 管理 → **版本管理** → 找到刚上传的开发版本 → 「提交审核」
2. 提交前确认这几项（都是常见驳回原因）：
   - ✅ **《用户隐私保护指引》已配置并审核通过**——里面必须勾选「选择聊天文件」等实际用到的能力。
     **未配置时 `wx.chooseMessageFile` 会直接报 `scope is not declared in the privacy agreement`**，主入口不可用。审核有周期，**这是最该先启动的一项**。
   - ✅ 服务类目与实际功能一致
   - ✅ 首页、功能页有清晰的用途说明（审核员看不到你的方案文档，只能看小程序本身）
   - ✅ `app.json` 里 `supportedMaterials` 的 `name` 含 `${nickname}`，`desc` ≤22 字（`scripts/check.js` 第 7 节会拦住写错的情况）
3. 审核通过后 → 「发布」。**发布这一刻才是「上线」，赛事要求的 7.17–10.17 窗口看的是这个时间。**

## 六、常见报错对照

| 现象 | 原因 | 处理 |
|---|---|---|
| `listen EACCES ... 3799` | 用了开发者工具 CLI | 改用 `miniprogram-ci`（即本脚本） |
| `未配置IP白名单` / `invalid ip` | 公众平台没配 IP 白名单 | 去「小程序代码上传」页配，或选不限制 |
| `-1 系统错误，错误码：-80011` 之类 | 密钥与 AppID 不匹配 | 确认 `.key` 是在**同一个 AppID**下生成的 |
| `cloud function deploy failed` | `miniprogram-ci` 稳定版的云函数能力 | 先试 `npm i -D miniprogram-ci@beta`；仍不行就改用开发者工具里**右键 `cloudfunctions/parseNotice` → 上传并部署：云端安装依赖**（这条路径一定可用，只是要手点） |
| 小程序里 `wx.cloud.callFunction` 失败 | `ENV_ID` 没改 / 云函数没部署 / 集合不存在 | 依次核对：`app.js` 的 ENV_ID、云函数列表里有没有 `parseNotice`、有没有建 `notices` 集合 |
| `scope is not declared in the privacy agreement` | 隐私指引没声明该能力 | 公众平台配置《用户隐私保护指引》并等审核通过 |

### 一处我未验证、先如实标注

**`miniprogram-ci` 的云函数部署能力，我没有在本机实测过**——因为缺 AppID 和密钥，跑不到那一步。官方文档写了 `ci.cloud.uploadFunction({ project, env, name, path, remoteNpmInstall })` 存在，但同时有第三方资料提到「云函数上传可能需要 `miniprogram-ci@alpha` 版本」。所以：

- 我按官方文档的签名把代码写好了
- 如果稳定版报错，**退路是开发者工具 GUI 的右键部署**，那条路一定可用
- 这个不确定性我不当成结论用
