## 1. 现状梳理

### 1.1 第一版已具备的核心功能（已稳定，第二版不动）

| 模块           | 现状                                 | 评价                     |
| ------------ | ---------------------------------- | ---------------------- |
| 三个入口         | 聊天素材（scene 1173）/ 相册拍照 / 纯文字       | 入口设计是本项目最强的差异化点，保持     |
| 解构内核 `core/` | Schema v1.0、纯函数、不依赖 `wx.*`         | 质量高，全套单测在，第二版不动        |
| 风险识别         | 5 类风险码（催办话术/个人收款/金额异常/权威话术/站外引导）   | 有独立 `risk-rules.js`，保持 |
| 时间解析         | 本地纯函数解析，模型只引用原文；70 条语料回归           | 这是最脆的一环，已有测试保护，不动      |
| 降级机制         | 低置信度不硬凹，整卡降级为原文+朗读                 | 设计原则正确，保持              |
| 幂等           | `requestId` → 确定性 `_id`，防老人连点重复扣额度 | 保持                     |
| 质量门禁         | 静态校验 77 项 + 单测 116 条，上传前强制跑        | 保持并扩展到新代码              |

**结论：解析链路（第一版的难点）已经稳定，第二版应绕开它，只改"最后一公里"。**

### 1.2 已知问题（代码事实，非推测）

#### 🔴 P0-1：「一键拨号」是死功能

`miniprogram/app.js:12` 里 `contactPhone: ''` 恒为空，注释写"留空时点击拨号会提示去设置"，  
但**全项目没有任何设置页面**（只有 index/result/history 三页）。

`grep contactPhone` 只命中两处：定义处、读取处。没有写入处。

→ **老人在结果页点「打电话」，永远只得到一句"还没设置电话号码"。**

#### 🔴 P0-2：「读给我听」是死功能

`utils/tts.js` 依赖「微信同声传译」插件（appid `wx069ba97219f66d99`），  
但 `app.json` **未声明 `plugins`**（tts.js 注释里明说"当前未声明，避免未添加插件时报错"）。

`getWechatSI()` 会 `requirePlugin` 失败 → 返回 null → `speak()` 直接 Toast「语音功能待配置」。

→ **点「读给我听」，永远只得到一句"语音功能待配置"。**

#### 🔴 P0-3：「保存卡片到相册」完全没有实现

`app.json` 里已经声明了权限：

```json
"permission": { "scope.writePhotosAlbum": { "desc": "用于保存行动卡图片，方便老人反复查看" } }
```

但全项目 `grep saveImageToPhotosAlbum|canvas` **零命中**。权限声明了，功能没写。

→ 老人想存下来反复看，目前做不到。

#### 🟡 P1-4：历史只存本地，换设备即丢

`utils/store.js` 用 `wx.getStorageSync`，最多 50 条，全在本地。  
云端 `notices` 集合确实在落库（`persist` 默认开），但**数据不回流前端**——  
它只用于按 `requestId` 幂等去重，语义上是"解析缓存"，不是"用户历史"。

→ 老人换手机、清缓存、重装微信，历史全没了。

#### 🟡 P1-5：一处注释与实现不符

`config.js` 里 `persist` 的注释写"history 依赖它"，但 history 实际完全走 localStorage，  
并不依赖云端落库。属于文档债，第二版顺手纠正，避免后人据此改错。

#### ⚠️ 待你确认的三项（未验证，不敢下结论）

| 项          | 现状                                                   |
| ---------- | ---------------------------------------------------- |
| 三个真机入口是否都通 | 代码写成，但**我没在真机上跑过**。`chooseMessageFile` 模拟器不支持        |
| AI 额度      | 当前 `aiProvider: 'cloudbase'`（云开发托管）。大赛免费额度状态**需你确认** |
| 隐私协议声明     | 是否已在后台提交并审核通过？未通过则主入口仍会报 `scope is not declared`     |

### 1.3 移动端体验短板

**已确认的结构性短板：**

- 无 `tabBar`，三个页面只能靠页内按钮跳转，老人在结果页容易迷路
- 加载反馈只有一句静态文案「正在识别通知…」，而模型超时上限是 **45 秒**。  
  老人面对 45 秒无变化很可能反复点，虽然有幂等保护不会重复扣费，但体验极差
- 图片上限 5MB，老人手机直拍的群截图常常接近这个量级，超限会直接失败且提示生硬

**⚠️ 推测性短板（需你的真机反馈确认，我没有体感数据）：**

- 字号是否真的够大（当前只有 `LIMITS` 限制字数，没有验证过实际视觉大小）
- 结果页信息密度对老人是否过高
- 首页三个入口按钮，老人能否理解"从聊天选"和"从相册选"的区别

## 2. 第二版目标

### 核心目标

> **让第一版已经承诺、但兑现不了的三个能力真正能用；同时让历史不再随设备丢失。**

### 可衡量达成标准

| #  | 标准                   | 怎么验                                   |
| -- | -------------------- | ------------------------------------- |
| G1 | 老人能在小程序内设置子女电话，并成功拨出 | 真机：设置页填号 → 结果页点击 → 手机真的拨号             |

## 3. 功能清单（P0/P1/P2）

### P0-0（新增，最高优先）· 让解析真的能跑通

#### P0-0a 核查并修正 AI 模型配置 —— ⚠️ 需你先在控制台看一眼

**为什么排第一**：如果模型名不对，所有解析都会失败并降级成"这条我没看懂"，
那么后面做的所有功能都是空转。**做任何新功能之前必须先排除这一项。**

**可疑点**：`config.js` 里 `model: 'deepseek-v4-flash'`，但云开发托管 AI 的公开资料显示
可用模型是 Hunyuan 系列（`hy3`），且旧混元模型已于 2026-05-30 下线。
两者是否冲突，**我从代码判断不出来，必须看控制台实际列表**。

**你去做的（1 分钟）**：云开发控制台 → 你的环境 → **AI** → 看可用模型列表里有什么。
把看到的模型名告诉我，我据此改 `config.js`。

**顺带看额度**（你问的）：同一处找「资源包」（或「AI 与 Agent 能力 → 资源包」），
能看到剩余 Token。也可在最新版开发者工具 → 云开发 → AI 模块查看。
用掉 80% / 90% / 100% 时会收到公众号提醒。

> 澄清：本项目用**多模态大模型直接读图**，不是 OCR。
> 只要模型配置对、且模型支持图片输入，图片就能读——**不需要另外接 OCR 服务**。
> 你怀疑的"没接 OCR"不是问题所在。

#### P0-0b 新增「粘贴文字」入口

**现状**：首页只有两个图片入口，`index.wxml` 提示第 2 条写着"群里发的是文字 → 先截个图"——
说明设计时就把纯文字让位给了截图。**根本没有文字输入框**，这是"纯文字没跑通"的直接原因。

**实现思路**：
- 首页加第 3 个入口「粘贴文字」→ 一个输入框页（或内联展开 textarea）
- 云函数 `parseNotice` **已经支持** `rawText`，不用改云函数，工作量很小
- 对老人有独立价值：子女可以帮着把文字复制过来

**工作量**：小（纯前端）

### P0-1（新增）· 字号统一放大

**现状（已量化）**：全项目最小字号 **28rpx ≈ 14px**（history 页 2 处），
30rpx ≈ 15px 共 6 处。对长辈来说这两档都太小。

**实现思路**：
- 建立下限：正文 ≥ 34rpx（17px），辅助说明 ≥ 32rpx（16px），**消灭 28/30rpx**
- 抽出字号 token 集中管理，避免以后再散落
- 大标题 52rpx 保持（已经够大）

**为什么与死功能同级**：产品叫"明白卡"，核心价值是"看得清"。
字号不行 = 核心价值不成立，比任何新功能都重要。

**工作量**：小（纯样式）

#### P0-1 设置页 + 紧急联系人

- **实现思路**：
  - 新增 `pages/settings/settings`（第 4 个页面）
  - 号码存本地 `wx.setStorageSync`，同时云端备份（见技术方案）

    （而不是像现在这样只弹一句没用的 Toast）
  - 支持存 1–2 个联系人（"孩子"、"老师"），符合真实场景
- **工作量**：小

#### P0-2 启用语音朗读（TTS）

- **价值**：产品的名字叫"明白卡"，核心价值是"看不懂也能听懂"。朗读不通 = 核心价值缺一半。
- **实现思路**：
  - **需要你在后台做一步**：小程序后台 → 设置 → 第三方设置 → 插件管理 → 添加「微信同声传译」（appid `wx069ba97219f66d99`）
  - 我做：`app.json` 加 `plugins` 声明

    **即使插件始终没配好，用户也不能面对一个只能弹 Toast 的按钮**

- **风险**：插件添加可能需要审核；若失败，必须有替代方案（见 P0-2 的降级改造）

#### P0-3 卡片保存为图片

- **价值**：老人不会每次都重新解析同一条通知，"存下来反复看"是刚需，且权限早就声明了。
- **实现思路**：
  - `canvas` 绘制行动卡（标题/行动项/截止/金额/风险）

## 4. 技术调整

### 4.1 总体原则

**解析内核（`cloudfunctions/parseNotice/core/`）一行不改。**  
第二版的所有改动都在：小程序端页面、存储层、以及新增的轻量数据集合。

### 4.2 数据模型

#### Schema：1.0 → 1.1（仅增不改）

行动卡契约本身**不改**。若确需加字段，只允许**新增可选字段**并给默认值，  
保证旧卡（本地已存的 50 条）能被新版正常渲染。

理由：体验版已经在跑，本地可能已有真实历史数据。改契约 = 用户数据报废。

#### 新增集合：`settings`（用户设置）

存紧急联系人。结构：

```
settings/{openid}
  contacts: [{ name: '孩子', phone: '138...' }, ...]
  updatedAt
```

#### 新增集合：`history`（用户历史备份）

```
history/{autoId}
  _openid
  cardId          // 与本地 store 的 id 对齐，用于去重
  card            // 完整行动卡（Schema 1.0/1.1）
  createdAt
```

### 4.3 为什么不需要新云函数

**关键决策：设置与历史都走「小程序端直连云数据库」，不新增云函数。**

理由：

- 云开发数据库权限设为「仅创建者可读写」后，**天然按 openid 隔离**，安全性等价
- 现有 `parseNotice` 云函数已部署且稳定，不动它 = 不引入回归风险
- 省掉一次云函数部署（那需要你在开发者工具右键操作，是流程上的摩擦点）

代价：写操作要在小程序端做，需要给 `history` 集合配「仅创建者可读写」权限。  
⚠️ 这一点我没有实测过前端直写的权限表现，落地时先小范围验证。

### 4.4 历史同步策略（兼容优先）

```
本地 storage = 权威（离线可用，老人弱网也能看）
云端 history = 备份

写入：新增卡片 → 先写本地 → 异步补写云端（失败静默，不影响主流程）
读取：启动时合并 → 以 cardId 去重 → 本地优先
迁移：首次升级检测到本地有数据、云端为空 → 批量补写云端
```

这样即使云端同步彻底失败，**老人的使用体验也不退化**——这是最重要的约束。

### 4.5 `app.json` 改动

- 新增 `plugins`（微信同声传译）
- 新增 `pages/settings/settings`
- ⚠️ 加 `tabBar` 需谨慎：会改变现有导航习惯，且首页是入口页不适合做 tab。  
  建议**暂不加**，先用页内导航解决迷路问题（更小的改动，可验证）

### 4.6 质量门禁扩展

新增代码必须纳入现有 `scripts/check.js`。新增两项检查：

- 禁止在 `core/` 下引入 `wx.*` / `cloud.*`（保护纯函数边界）
- 新增页面的 `wxml` 必须包含无障碍相关属性（`aria-label` 等），为朗读与读屏准备

### M1 · 打通死功能（最关键的一步）
